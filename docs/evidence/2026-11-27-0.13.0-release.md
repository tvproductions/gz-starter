# GZ Starter 0.13.0 release

The maintainer authorized publication of **0.13.0** on November 27, 2026.
Published baseline **0.12.1** at `a1c3550eac441b0a7beaddc66fb00c58ce0f1e6a`
advances to **0.13.0 / minor**. The
[selected scope](../../ROADMAP.md#selected-0130-minor-scope--versioned-native-marketplace-name-november-27-2026)
names the native catalog after each release and carries the unreleased 0.12.2
[dependency refresh](2026-11-23-dependency-maintenance.md). Plugin IDs change
once per upgrade, so this is a minor under the adoption contract.

## Change

Codex caches one checkout per marketplace name. Every adopter declared the
shared `skills-first-starter`, so projects pinned to different starter
revisions overwrote each other's cached pins. From 0.13.0 the catalog is
`gz-starter-0-13-0`. `configure` retires an earlier starter entry only when it
is exactly starter-written and every activation holds the starter default;
anything else stops the update with no writes. `localize` keeps the name of the
release recorded in the project lock. See the
[update note](../updating.md#versioned-native-marketplace-name). Reviewed in
[PR #17](https://github.com/tvproductions/gz-starter/pull/17), merged as
`0afecf327dabb8c30b91a74012aa82ef7e2acaaa`.

## Exact-candidate acceptance

On `0afecf327dabb8c30b91a74012aa82ef7e2acaaa`, Linux x86_64, uv 0.13.10,
managed CPython 3.14.10:

- `uv sync --locked --all-groups --extra verification` succeeded.
- `pre-commit run --all-files`: Ruff check, Ruff format, ty and unittest
  passed. Unittest ran 150 tests, 2 skipped.
- `gz-starter validate` passed: bundle pins and both catalogs match, named
  `gz-starter-0-13-0`.
- `uv build --no-sources` built the sdist and wheel;
  `tools/verify_distribution.py` passed wheel resources, sdist contents and
  isolated installed CLI checks.
- Both jobs of [producer CI](https://github.com/tvproductions/gz-starter/actions/runs/45988831941)
  passed for that commit, including the X-Plane baseline on CPython 3.12.

The checking environment exported `UV_PYTHON_PREFERENCE=only-managed`. uv
0.13.10 rejects that variable together with the verifier's `--managed-python`
flag, so verifier fixture tests fail while it is set. The results above were
run with it unset. Adopters that export the variable will see the same
`uv lock --check failed (exit 2)` block; this is recorded as an open finding.

## Retained limits

- Native discovery of the new catalog name from a fresh Codex or Claude Code
  session is **not verified** for this release.
- The private hosted macOS ARM64 and Windows x64 verification run was not
  repeated for 0.13.0. The latest hosted qualification is the 0.12.1 run
  recorded in the [0.12.1 candidate acceptance](2026-11-22-0.12.1-candidate-acceptance.md),
  which covered that release's verifier state-directory changes. This
  release does not change the verifier source.
- Release acceptance stays conditional under the
  [standing cognitive deferral](../engineering/cognitive-integration.md#starter-wide-qualification-deferral):
  **DEFERRED / UNKNOWN**, ceiling 15.
- Backplane remains disabled; its host readiness is open. Embedded XPPython3
  execution remains unverified.
