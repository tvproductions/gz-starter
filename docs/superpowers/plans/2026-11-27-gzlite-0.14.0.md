# gzlite 0.14.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename gz-starter to gzlite 0.14.0 and add `migrate`, `freshen`, `project-settings`, `portability`, `vendor` and `catalog check`, so every adopter can move to gzlite in one reviewed, deterministic step and gz-skills can drop all executable code.

**Architecture:** The existing stdlib-only package `skills_first_starter` is renamed `gzlite` and keeps its configure/localize/status/verify core. Each new command is one focused module with a pure planning function and a thin CLI handler; `migrate` and `freshen` share one fingerprint helper and one embedded release-history data file generated from the starter's own tags.

**Tech Stack:** Python 3.14, standard library only for the base helper (`pyyaml==6.0.4` only in the `verification` extra), unittest, uv, ruff, ty, import-linter.

**Spec:** `docs/superpowers/specs/2026-11-27-gzlite-rename-and-tool-split-design.md` (approved 2026-11-27) and its decisions log beside it. Read both before any task.

## Global Constraints

- Python `>=3.14,<3.15`; base helper standard-library only; `pyyaml==6.0.4` only in `gzlite[verification]`.
- Tests are unittest only (pytest is banned). Run Python only as `uv run --locked python …`.
- Every path passes `paths.space_free`; state folder is `.gzlite/`; legacy `.gz-starter/` and `.skills-first/` are refused by everything except `migrate`.
- Adoption commands print `json.dumps(result, indent=2)` and exit 0; refusals print `adoption blocked: …` to stderr and exit 2. Check commands (`portability`, `catalog check`) exit 0 clean, 1 findings, 2 usage.
- Every writing command previews by default; `--apply` writes. `migrate` and `freshen` also require `--fingerprint <64 hex>` with `--apply` and write only if it matches the recomputed fingerprint.
- Supported hosts: Codex, Claude Code, OpenCode 2.x only.
- The gate never touches the network.
- Names: distribution `gzlite`; import package `gzlite`; CLI `gzlite` with aliases `gz-starter` and `skills-first-starter`; marketplace `gzlite-0-14-0`; update skill `gzl-update`; display name "GZ Lite".
- Historical references (CHANGELOG entries, evidence, past ADRs, handoffs) are not rewritten.
- Section 9 ADRs each need the maintainer's explicit approval before the task that depends on them starts. Tagging, publishing, installing and `gh repo rename` need the maintainer's explicit go-ahead at the time.
- Never bypass hooks. Regenerate resources (`tools/package_resources.py`) after changing any resource source.

## Review Focus

1. A Windows adopter whose managed files have CRLF line endings (git `autocrlf`) — a line-ending-only difference must count as unchanged, not as a hand edit. Test in Task 10.
2. An adopter with both `.claude/` and `.codex/` configured while the lock records one host — migrate must update every configured host. Test in Task 10.
3. A hand-written lock with `starter.release` instead of `starter.version` (xplane-health) — must be read and normalized, not refused. Test in Task 10.
4. `opencode.jsonc` present instead of `opencode.json` — migrate and freshen must edit the file that exists. Test in Task 10.
5. Running `migrate` or `freshen` again right after `--apply` — must report nothing to do and write nothing. Tests in Tasks 10 and 11.
